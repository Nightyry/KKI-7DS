Пожалуйста, спроектируй простую клиент-серверную архитектуру для этого конструктора с учетом правил:
1. Я совершенно не знаю программирования. Пиши код (C# для Unity и Go для сервера) с подробнейшими комментариями на русском языке, объясняя каждую строчку "на пальцах".

Вот как устроен упрощенный Конструктор полей боя на экране в Unity:
- Текстовые поля: Название поля боя (например, "Ночной клуб" или "Подпольное казино"), Описание арены.
- Визуальная часть: Игрок загружает фоновое изображение стола. Перед отправкой на Go-сервер Unity должен автоматически сжать картинку до разрешения 1024х1024 или 512х512 пикселей (формат JPEG/WebP), чтобы файл весил не более 200–300 КБ (защита от тяжелых 4К файлов).
- Аудио часть: Выбор фонового музыкального трека (просто ID или название трека из списка доступных в игре).

Логика модерации на сервере Go:
- Игрок отправляет название, ID музыки и сжатый файл картинки.
- Сервер Go сохраняет это во временное хранилище (базу данных) со статусом "На модерации". На стороне сервера обязательно должна стоять жесткая проверка на размер файла в байтах: если файл подозрительно тяжелый, сервер отклоняет запрос.

Пожалуйста, покажи структуру JSON для хранения такого визуального поля боя, а также понятный код на Go для сервера и C# для Unity, который управляет загрузкой, сжатием картинки и отправкой этих данных на модерацию.
