Привет! Мы переходим к проектированию "Системы матчмейкинга и экрана подготовки к PvP" для нашей онлайн-ККИ на Unity 6 и Go. Нам нужна надежная архитектура, которая свяжет выбор колоды в Unity и серверную очередь поиска игроков на Go.

Пожалуйста, строго соблюдай правила:
1. Я абсолютно не знаю программирования. Пиши код (C# для Unity и Go для сервера) с подробнейшими комментариями на русском языке, объясняя каждую строчку "на пальцах".
2. Код должен быть клиент-серверным: Unity только отправляет запросы и показывает анимации, вся логика подбора и проверок происходит на сервере Go.

Вот как устроен процесс на Экране подготовки к PvP в Unity:
- Игрок видит список своих колод. Он выбирает одну из них.
- Кнопка "Поиск противника" становится активной ТОЛЬКО если в колоде ровно 30 карт.
- При нажатии на "Поиск противника", Unity отправляет на сервер Go запрос, содержащий: ID Игрока, его текущий Рейтинг (MMR) и ID выбранной колоды.
- В Unity включается интерфейс ожидания (таймер поиска). Появляется кнопка "Отмена", которая позволяет выйти из очереди.

Логика Матчмейкера на сервере Go:
- Сервер принимает запрос и помещает игрока в структуру данных "Очередь поиска" (массив/список).
- Сервер каждые несколько секунд ищет пары игроков. Алгоритм должен использовать расширяемый диапазон рейтинга (например: первые 5 секунд ищем соперника с разницей рейтинга +-50, затем +-100, затем +-200, чтобы не было бесконечного ожидания).
- Когда пара игроков с подходящим рейтингом найдена, сервер удаляет их из очереди и создает объект "Матч".
- Сервер случайно выбирает ID Поля боя из базы данных одобренных арен и случайно определяет, кто из двух игроков будет ходить первым.
- Сервер отправляет обоим игрокам ответ с данными матча (ID соперника, его имя, ID поля боя, и флаг "Ходишь ли ты первым").

Пожалуйста, покажи:
1. Как выглядит структура данных Очереди поиска на Go.
2. Код на Go (с подробными комментариями), реализующий логику подбора игроков по рейтингу и расширение диапазона поиска.
3. Код на C# для Unity, который отправляет запрос на поиск, запускает таймер и умеет обрабатывать отмену поиска.
