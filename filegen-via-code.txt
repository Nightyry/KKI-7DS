Привет! Я разрабатываю онлайн-ККИ (коллекционную карточную игру) на движке Unity 6, серверная часть пишется на Go (Golang). За геймплейный ориентир мы берем Hearthstone. 

Сеттинг игры: борьба человека со своими внутренними зависимостями (Никотин, Лудомания, Алкоголизм и т.д.). Сейчас фокус строго на онлайн-PvP режиме. 
Я абсолютно не знаю программирования от слова совсем. Мне нужна полная, пошаговая архитектура игры, логика и шаблоны данных.

ПОЖАЛУЙСТА, СТРОГО СОБЛЮДАЙ СЛЕДУЮЩИЕ ПРАВИЛА:
1. НЕ придумывай за меня конкретные карты, персонажей или баланс. Создай гибкие Конструкторы (структуры данных), параметры в которых игроки и я сможем настраивать через интерфейс (UI).
2. Архитектура должна быть клиент-серверной: Unity — это просто "телевизор" для показа анимаций, а сервер на Go — это "мозг", который хранит данные, проверяет действия и считает математику матча, чтобы защитить игру от читеров.
3. Обязательно снабжай код (C# для Unity и Go для сервера) подробнейшими комментариями на русском языке. Объясняй каждый шаг, архитектурное решение и термин так, будто рассказываешь ребенку или человеку без технического образования.

### ЧАСТЬ 1: СТРУКТУРА ИНТЕРФЕЙСА (ЭКРАНЫ В UNITY)
Опиши логику переходов и покажи, как связать между собой следующие экраны:
1. Экран 0 (Авторизация): Ввод логина/пароля. Запрос идет на Go для загрузки профиля игрока.
2. Экран 1 (Главное меню): Кнопки: Начать игру, Голосование, Мастерская, Коллекция, Профиль, Настройки, Выход.
3. Экран 2 (Профиль): Внутри Настроек/Меню. Смена ника, привязка почты, статистика опыта игрока (кол-во матчей, рейтинг MMR).
4. Экран 3 (Подготовка к PvP): Выбор колоды из 30 карт, кнопка перехода в Коллекцию, кнопка "Поиск противника" (активна, только если колода валидна). При поиске включается таймер и кнопка "Отмена".

---

### ЧАСТЬ 2: МОДУЛЬ «МАСТЕРСКАЯ И ГОЛОСОВАНИЕ» (UGC-КОНТЕНТ)
Спроектируй структуру данных (JSON) и логику для раздела "Мастерская", где игроки создают контент:

1. Конструктор Карт: Поля ввода параметров (Мана, Атака, Здоровье, Название, ID Обложки). Выпадающий список "Эффекты карты", где эффект собирается по схеме: [Триггер/Условие, например: При разыгрывании] -> [Действие, например: Нанести урон] -> [Числовое значение].
2. Конструктор Персонажей: Поля ввода параметров (Название класса, Стартовое Здоровье, Стартовая Броня, ID Аватара). Выпадающий список "Активная способность" (Сила героя за ману) и выпадающий список "Пассивная Черта" (работает автоматически). У каждого героя есть скрытый ID Класса.
3. Конструктор Полей боя: Упрощенный вариант. Только визуальная функция (Название, Описание, фоновое изображение стола, ID музыкального трека).
4. Баланс-метр (Шкала Искушения): Алгоритм в Unity, который в реальном времени оценивает вес карты/героя на основе соотношения стоимости маны и силы статов/эффектов. Красит индикатор в цвета от зеленого ("Сбалансировано") до красного ("Дисбаланс").
5. Модуль защиты (Анти-4К): Логика в Unity, которая автоматически сжимает загруженные игроком картинки обложек до разрешения 512х512 пикселей (до 200 КБ). На стороне сервера Go должна стоять жесткая проверка размера файла в байтах.
6. Серверная модерация и Анти-дубликат: Если на Go прилетает карта/герой/поле с параметрами, точь-в-точь как у существующих, но с другой картинкой — сервер одобряет её, но помечает как "Предложение альтернативного скина". Также создай раздел "Мои предложения" с историей и статусами фидбека (Принято / Отклонено по причине).
7. Раздел "Голосование" в Главном меню: Игроку выдается пачка из 10 карт (7 новых предложений и 3 старые карты из игры для проверки баланса). Сервер Go должен рассчитывать "Вес голоса" (Voice Weight) игрока на основе его опыта из Профиля (голос ветерана весит больше).

### ЧАСТЬ 3: МОДУЛЬ «КОЛЛЕКЦИЯ И ДЕКБИЛДИНГ»
Спроектируй JSON и логику проверки колоды на сервере Go:
1. При создании колоды игрок выбирает Героя. Включается классовый фильтр: можно брать только Общие карты (Класс = 0) и карты этого Героя. Архитектура должна поддерживать будущие двухклассовые (гибридные) карты.
2. В колоде должно быть строго 30 карт. Используй стандартные редкости: Обычная, Редкая, Эпическая (максимум 2 копии в колоде) и Легендарная (строго 1 копия в колоде).
3. Напиши логику валидации колоды на сервере Go при нажатии кнопки "Сохранить".

### ЧАСТЬ 4: ИГРОВОЕ ЯДРО (МАТЧМЕЙКИНГ И ПОШАГОВЫЙ БОЙ)
Спроектируй логику проведения матча:
1. Матчмейкинг на Go: Принимает запрос от Unity (ID Игрока, MMR, ID Колоды). Ищет соперника с помощью алгоритма расширяющегося диапазона рейтинга (каждые 5 секунд расширяет рамки поиска MMR, чтобы не ждать вечно). При нахождении пары создает "Матч", выбирает случайное поле боя и случайно определяет, кто ходит первым.
2. Тематический Муллиган ("Цена искушения"): На старте Первый игрок получает 3 карты, Второй — 4 карты + карту "Монетка" (+1 временная мана). Добавь кнопки риска:
   - Общая "Поддаться искушению": Сбросить все карты и гарантированно получить карты дешевле 3 маны, но потерять 3 стартовых здоровья героя.
   - Классовая для Лудомана "Ставка на старте": Попытаться добрать лишнюю карту. Шанс 50/50: либо бесплатно, либо карта приходит, но наносит герою урон, равный своей стоимости. Вся математика считается на Go.
3. Пошаговый бой: Оба игрока начинают свой первый ход строго с 1 единицы маны (текущая 1, макс 1). Каждый ход максимум растет на 1 (до 10). В начале хода мана восстанавливается, и сервер выдает 1 карту из колоды.
4. Механика атак (в стиле Hearthstone): Существа при выходе на стол "спят". Игрок может атаковать выбранным существом карту врага (взаимный урон по показателю Атаки) или Лицо вражеского героя (урон по здоровью/броне). Сервер Go должен проверять наличие вражеских карт со свойством "Провокация" (Таунт).
